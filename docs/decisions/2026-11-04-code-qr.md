# Code QR du lien d'invitation

## Contexte

Pour inviter quelqu'un dans la même pièce, recopier un lien ou dicter un code est malcommode : le salon affiche
le lien d'invitation en code QR, que l'on scanne avec l'appareil photo d'un téléphone. Calculer un code QR
demande un encodage précis (versions, correction d'erreurs Reed-Solomon, masques) : ce n'est pas du code à
réécrire dans un projet de cours.

## Décision

- **`qrcode-generator` 2.0.4** (licence MIT, aucune dépendance, types TypeScript fournis), épinglée à cette version
  exacte. On ne lui demande que la matrice (`isDark(ligne, colonne)`), dans `web/src/qr.ts`.
- **Dessin en SVG par React** (`components/QrCode.tsx`) : un seul chemin, une case par carré sombre. On n'insère
  jamais le HTML produit par la bibliothèque (`createSvgTag`), ce qui éviterait `dangerouslySetInnerHTML`.
- **Toujours noir sur blanc**, quel que soit le thème, avec la marge de 4 cases de la norme : beaucoup de lecteurs
  ne reconnaissent pas un code inversé. Correction d'erreurs « M » (15 %).
- Vérifié dans le navigateur : le code affiché est relu par le lecteur de codes-barres du navigateur
  (`BarcodeDetector`) et redonne exactement le lien d'invitation.

## Alternatives écartées

- **`qrcode`** : très utilisée, mais trois dépendances (dont `yargs`, pour sa ligne de commande).
- **Code QR fabriqué par le serveur** (caisse Rust) : une route de plus, et une image à transférer, pour un calcul
  que le navigateur fait instantanément.
- **Service en ligne de génération d'images** : enverrait le lien de la partie à un tiers.

## Conséquences

- Une dépendance de plus dans `web/package.json`, surveillée par `npm audit` dans la CI.
- Le code QR ne contient que le lien d'invitation (le code de la partie), jamais de jeton.
